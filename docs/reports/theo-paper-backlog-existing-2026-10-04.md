## 1. `mogollon-pithouse-sites-across-the-upper-gila` — built, gate-passed, not shipped

`3b9ac686-1796-4ad4-92fa-2354c0cc21de`

**This is the one paper still carrying known defects, and it is repaired but withheld.**
The owner decided on 04.10.2026 to hold it until a coherence run is possible, and it
was never shipped. Meanwhile:

- `build_status.json`: `built: true`, `gate_passed: true`, no failures. The blocker
  that was expected here (`undefined_title_terms`) is gone. **The repair is ready to
  ship as it stands** — `ship_paper.py 3b9ac686-1796-4ad4-92fa-2354c0cc21de` with a dry
  run first, exactly like every other paper.
- 8 of its 46 findings are `contradicted`, 18 `unsupported`, 9 `misattributed`.

What the repair fixes, so the next session can judge whether holding is still right:

1. **Two different sites are run together.** The paper equates **Mogollon Village**
   (LA 11568, ~50 pithouses, type-site work by Emil W. Haury) with **the SU Site**
   (sixteen houses, named after nearby SU Canyon, excavated by Paul S. Martin and
   John B. Rinaldo in 1939, 1941, 1946). It does so inconsistently: some paragraphs
   assert the identity outright, others merge the two excavations' attributes and
   then attribute the SU Site's **Alma Plain / Alma Rough** wares to Mogollon Village.
   The paper is also internally inconsistent about it — a `supported` finding in ¶5
   repeats the equation while three `unsupported` findings elsewhere refute it.
2. **A calibrated range is read as a duration.** "Spans nearly nine centuries" comes
   from the outer calibrated bounds cal AD 5–130 to cal AD 895–990; the article itself
   says activity for **at least 615–705 years**. The repair narrows the sentence to
   "at least six to seven centuries … within calibrated bounds of cal AD 5–130 to
   cal AD 895–990".

**Decide before shipping:** the owner's reason for holding was a *coherence run* — a
pass that checks the paper against itself. That has not happened. Shipping the repair
fixes the two factual errors and leaves the coherence question open; not shipping
leaves a known-wrong date on a live page.

## Tooling the next session should not rebuild

All in `C:\tmp\papers\`.

| tool | what it does, and the trap it already handles |
|---|---|
| `build_corrected.py` | audit → corrected text. Guards: unique anchors, overlap, reference grammar via the production parser, gate-gated write, a failed re-source aborts instead of shipping a text with a silently lost repair, and a dead-image strip that only removes paths `image_status.json` proves are 404 — an unconditional strip would have deleted 31 working images on 04.10. |
| `ship_paper.py` | dry run → apply → journal read-back, and refuses a `corrected.md` that was built from a different audit than the one on disk. |
| `image_probe.py` | HTTP HEADs every image reference and caches the status. **Run it before any image change.** |
| `diff_live.py` | prints the real differing lines between the live report and a local build. `check_live_matches_local.py` only compares lengths and treats ±2 as CRLF noise — that is how a one-character repair stayed live unnoticed. |
| `aggregate_findings.py`, `citation_coverage.py`, `seam_scan.py`, `extract_backlog.py` | the measurements behind the defect report and this backlog. Re-run them rather than quoting a number. |
| `IMAGE_BRIEF.md`, `RESOURCE_BRIEF.md`, `AGENT_TASK.md` | the agent contracts. |

**One rule the tooling learned the hard way:** a send path must be idempotent per
*input hash*, never per boolean flag. `ship_ready.py` checked `built == true`, which
stays true after a successful build, and re-sent 33 bundles — 42 byte-identical
correction entries on 22 live papers. It is now guarded by `shipped.json` plus the
audit hash, and the guard is proven to send 0 on a second run.
