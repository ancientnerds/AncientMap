5 Why Dense + BM25 + Rerank

Dense only — "Gobekli Tepe" query returns semantically similar sites (temples, Neolithic) but may rank the exact match lower than a site with a similar description.
BM25 only — "Gobekli Tepe" returns exact keyword matches. But "ancient temple complex in Turkey" returns nothing if no document has that exact phrase.
Dense + BM25 + Rerank — BM25 catches the exact name. Dense catches the semantic concept. RRF fuses both. Reranker picks the best. Anthropic research: 67% fewer retrieval failures vs dense alone.

6 What’s Inside Each Chunk

1 entity = 1 Qdrant point. No text splitting needed — our data has natural boundaries.

Site Chunk (1 row in unified_sites)

name primary name, e.g. "Masada"
site_type normalized — "Fortification" (from fortress/fort/hillfort/citadel/oppidum)
period_name human label — "Roman"
period_start/end year (neg=BCE) — -31 / 73
country modern country — "Israel"
description varies wildly by source (see below)
alt_names joined alternates — "Metzada, מצדה"
content_titles linked resource names
lat/lon coordinates for map

News Chunk (1 row in news_items)

headline AI-extracted topic title (first fact)
summary bullet-point facts joined as text
facts JSONB array of 3–8 specific claims
significance 1–10 importance score
news_category "discovery", "dating", "general", etc.
site_name_extracted linked site name
site_id FK to unified_sites (nullable)
timestamp_seconds deep link into YouTube video

Data quality — ancient_nerds only

Sites (ancient_nerds, 5K+) curated
Hand-curated sites with real descriptions, alternate names, content links, and Wikipedia data.
Only source_id = 'ancient_nerds' is indexed — no DARE stubs, no Pleiades one-liners.
News (Claude-extracted) richest
AI distills full YouTube transcripts into structured facts + summary. Contains specific findings, dating methods, researcher names. The signal — not the raw transcript noise.

7 Query Capability — What Works vs What Doesn’t

Example query: “Are there any sites in the Mediterranean, that were part of the early Roman empire, fortresses with human remains found older than the site itself? Show them on the globe!”

Constraint
Searchable?
How / Why Not
“Mediterranean”
Partial
No “region” field. LLM must enumerate countries (Greece, Turkey, Italy, Tunisia…) or embedding catches it semantically. No geo-bounding-box.
“early Roman empire”
Partial
period_name = "Roman" works, but “early” vs “late” is NOT distinguished. LLM can filter by period_start range if needed.
“fortresses”
Yes
site_type = "Fortification" — normalized from fortress/fort/hillfort/citadel/oppidum. Clean metadata filter.
“human remains found”
Unreliable
Only in free-text description if the curated entry mentions it. This detail lives in excavation reports we don’t have.
“older than the site”
Indirect
No structured artifact-dating field, but news facts or site descriptions may mention it. Haiku can reason over retrieved context to find clues (e.g. “remains predating the structure”). Not a metadata filter — depends on what the text contains.
“show on the globe”
Yes
All sites have lat/lon. Auto-retrieve emits sites for immediate map highlighting.

✓ Works Reliably

“Show me Roman fortresses in the Mediterranean”
• Auto-retrieve embeds query → dense vector catches “Roman fortification Mediterranean”
• BM25 catches exact keyword “fortress” / “Roman”
• LLM uses search_sites(type=”Fortification”, period=”Roman”, country=”Greece”) for follow-up
• All results have lat/lon → map highlighting works
• ~860ms to first token (single collection + Haiku)

⚠ Edge Case

“…with human remains older than the site”
• Site ages work fine — we have period_start/end on every site
• “Older than site” needs comparing individual find dating vs site founding
• No finds/artifacts table — individual objects within a site aren’t tracked
• News collection may surface this if a YouTube channel covered it
